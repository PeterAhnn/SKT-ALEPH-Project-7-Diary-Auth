# T06 작업 지침

- 상위 폴더의 `AGENTS.md`와 최신 사용자 지침을 따른다.
- 이 폴더의 공통 가이드, `docs/ASSIGNMENT.md`, `docs/PREPARATION.md`, `HANDOFF.md`를 읽는다. 공통 가이드·템플릿의 기준본은 상위 폴더이며 사본을 동기화한다.
- T06 전체 설명과 카드 1~5는 2026-09-30 기존 인증된 내장 브라우저에서 확인했다. 준비 문서의 요구사항을 구현·검증에 연결하고 미완료를 구분한다.
- 사용자 기록 주제는 ALEPH 공부·과제 진행이다. 실제 사용자 기록·공개 범위·판단·검사 결과를 만들어 쓰지 않는다.
- T06은 로그인 없는 실제 서버 DB 기반 Plan → Do → See 앱이다. 정확한 첫 화면 공개 안내, Plan 불변 이력, 실행과 계획 분리, 완료 중복 방지, 실제 집계 규칙을 유지한다.
- `contracts/pds-schema-v2.json`은 실제 DB 테이블·필드·관계·날짜 규칙과 일치하게 작성한다. 구현 전 추정 구조를 확정 계약처럼 작성하지 않는다.
- 제출은 `docs/SUBMISSION.md`에 관리한다. 정확한 확인 4항목·판단 3항목과 검증한 소문자 전체 커밋 `/commit/` URL을 유지한다. T06 결과물·소스 URL 모두 필수, 파일은 선택이다.
- T07에 전달할 T06 기준 커밋·실제 스키마·사용자 자료·검증 근거를 보존한다.
- 최신 사용자 지침에 따라 현재 열린 Codex 내장 브라우저를 기본으로 사용하고 페이지 문맥을 유지한다. 인증 없는 공개 접근·별도 자동 검증에는 격리된 gstack `/browse` 세션을 사용할 수 있다.
- `mcp__claude-in-chrome__*`를 사용하지 않는다. 개인 동기화 Chrome의 탭·탭 그룹을 자동화로 만들지 않는다.

## 과제 안내 확인과 읽기 정리 — 2026-09-30 사용자 확정

- 과제 번호나 이름을 받으면 실제 최신 과제 페이지의 전체 설명·모든 안내 단계·완주 체크리스트·제출 화면을 먼저 읽는다. 기본 5단계는 모두 확인하며 미접근 범위를 미확인으로 표시한다.
- 원문 확인과 상세 기록에서는 `왜 이걸 하는가`, `제출물`, `완주 체크리스트`, 단계별 `하는 일`, `첫 행동`, `통과 기준`, `막히는 지점과 확인 순서`, `남길 것`을 누락 없이 대조한다.
- 사용자에게는 목표 → 단계별 `해야 할 일·만들 기능·남길 것` → 중요한 검증/수량/계산 규칙 표 → 보고서·제출/보관 항목 → 현재 완료/미완료의 깔끔한 형식으로 보여준다. 공식 첫 행동·통과 기준·문제 확인 순서를 이 형식에 녹여 내용의 빠짐 없이 설명한다.
- `ALEPH-TASK-READBACK-TEMPLATE.md`로 `docs/TASK-READBACK.md`에 만들 결과 → 검증 행동·통과 결과 → 남길 화면/실제 기록/파일/검사 결과 → 보고서 구성 → 제출 항목을 구체적으로 연결하고 먼저 사용자에게 보여준다.
- 실제 수행 후 보고서를 작성하며 공식 제출 필수·선택·검토/보관 자료를 구분한다. 공식 요구와 AI 제안, 실제 기록과 합성 시험, 목표와 실제 결과를 구분한다. 실제 결과·사용자 판단을 만들거나 추가 PDF·첨부물을 임의로 필수화하지 않는다.
- 이 정리를 먼저 보여주는 것은 불필요한 승인 요청이나 작업 중단을 추가하는 조건이 아니다. 기존 승인 범위에서 이어 작업한다.
- 이전 브라우저 기본 규칙보다 최신 사용자 지시를 따른다. 로그인된 화면은 기존 Codex 내장 브라우저에서 읽는다. 로그인 정보와 분리한 공개 접근 확인 또는 반복 자동 검사가 필요한 경우에만 별도 gstack `/browse`를 사용한다. 개인 Chrome에 자동화 탭·탭 그룹을 만들지 않으며 `mcp__claude-in-chrome__*`를 사용하지 않는다.
