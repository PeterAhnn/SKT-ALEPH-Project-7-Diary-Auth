## 과제 목표와 최종 결과

**공식 목표:** T06 다이어리에 가입·로그인을 붙여 내 자료를 내 계정으로만 보게 한다. 무엇을 골랐고 왜 골랐는지, 소스 어디를 고쳤는지, 무엇을 직접 확인했는지, 아직 못 막은 것은 무엇인지 설명한다. 성공 요청과 거절 요청을 나란히 남겨 실제로 막히는 장면을 보인다. 인증을 붙인 앱을 서로 다른 실제 날짜 5일 동안 사용하면서 2일차 뒤·3일차 앞에 계획 규칙 하나만 바꾸고, 같은 지표로 전후를 비교한다.

공식 계획시간은 6~8시간이고 실제 사용 기간은 5일이다. 구현 시간을 채우는 것으로 실제 5일 사용을 대신할 수 없다. 채점은 제출물을 읽어서 하며 심사자가 학생의 계정으로 로그인하지 않는다. 진짜 계정 비밀번호를 제출하지 않는다.

최종 결과는 로그인 화면부터 열리는 HTTPS 앱, 실제 최종 T06 제출을 이어받은 고정 소스 이력, 여섯 항목의 인증 구현 설명서, 비밀값을 가린 요청·응답 근거, 실제 5일 기록 및 규칙 변경·집계 대조, 확인 4항목과 판단 3항목이다.

## 원문 확인과 상세 기록

### 왜 이걸 하는가

자물쇠를 붙였다는 설명과 실제로 잠겼다는 근거를 구분하는 과제다. 인증 구현과 함께 다른 사람이 확인할 수 있는 설명을 만든다. “막았습니다”라는 문장만으로 통과를 주장하지 않고, 요청과 응답에 막히는 장면을 남긴다.

### 공식 제출물

1. 결과물 주소: 첫 화면은 로그인 화면이며 내 기록은 로그인 뒤에만 보인다.
2. 소스 주소: 전체 소스 상태를 받을 수 있는 소문자 full commit이 포함된 HTTPS 고정 URL.
3. 인증 구현 설명서: ① 무엇으로 붙였나 ② 왜 그걸 골랐나 ③ 어디를 어떻게 고쳤나 ④ 안 열리는 것을 확인한 기록 ⑤ AI와 나 ⑥ 아직 못 막은 것.
4. 짧은 확인 방법 4줄: 어디로 가나요 / 세 단계 안에 무엇을 하나요 / 무엇이 보이면 통과인가요 / 안 될 때는 무엇이 보이나요.
5. AI와 내 판단 3줄: AI에게 맡긴 일 / 내가 직접 판단한 일 / AI 말을 따르지 않은 일(없다면 왜 없었는지).

설명서는 공식 제출 내용으로 필요하다. 제출 화면의 **확인 파일 첨부는 선택**이며 설명서의 전달 방식·파일 형식은 공식 안내에 별도로 지정되어 있지 않다. 공개 소스 문서로 연결하거나 허용 형식 파일을 첨부하는 방식은 **AI의 전달 제안이며 미확정**이다. 화면에서 확인 4항목·판단 3항목을 “권장”으로 표시해도 공식 기준과 후행 채점에는 평가 항목이므로 준비한다.

## 단계별 해야 할 일과 남길 것

### 1단계 · 무엇으로 붙일지 고르고, 이유를 적기

#### 하는 일

가장 먼저 코드보다 선택을 정한다. 직접 구현·라이브러리·인증 서비스 중 하나를 골라 이름과 이유를 설명한다. 가입·로그인·로그아웃이 실제로 되게 만들고, 무엇을 왜 골랐는지 제출문에 남기는 것이 완료 목표다. T06 다이어리에 이어 붙이고 T06의 내 자료를 내 계정으로 옮긴다. **선택은 아직 미확정**이며 이 문서는 사용자 대신 선택 이유를 만들지 않는다.

#### 첫 행동

1. 직접 구현·라이브러리·인증 서비스 가운데 하나를 고르고 이름과 버전을 적는다.
2. 함께 검토했지만 고르지 않은 방법을 하나 이상 적고 제외 이유를 한 문장으로 쓴다.
3. 가입·로그인·로그아웃을 붙이고, 로그인하지 않은 채 자료 화면 주소를 열어 로그인 화면이 나오는지 확인한다.

### 2단계 · 비밀번호를 어떻게 맡아 두는지 보이기

3. 같은 비밀번호로 계정 두 개를 만들어 저장값이 서로 다른지 확인한다.

## 설명서 구성과 근거 연결

설명서는 공식 제출 내용이며 다음 여섯 항목으로 나눈다. 아래는 **작성 계획**이다. 실제 선택과 구현·검증 이후 사실에 맞춰 채우고, 미수행·실패·미해결도 그대로 구분한다.

| 공식 항목 | 적을 내용 | 연결할 실제 근거 |
|---|---|---|
| ① 무엇으로 붙였나 | 인증 방식·이름·버전, 비밀번호 방법, 세션/토큰 | 실제 선택과 사용 버전·구성 |
| ② 왜 그걸 골랐나 | 실제 선택 이유, 검토한 대안 1개 이상과 제외 이유, 비밀번호 방법 선택 이유 | 사용자가 실제로 내린 판단 |
| ③ 어디를 어떻게 고쳤나 | 가입·로그인·로그아웃·자료 조회 네 흐름의 소스 위치, 소유자 거절 위치, T06 연속성 | 고정 소스 커밋의 파일·함수·흐름과 변경 |
| ④ 안 열리는 것을 확인한 기록 | 확인 다섯 가지 각각 성공/거절 쌍; 세션 무효화·양방향 요청·목록·무변경 등 전체 기준 근거 | 비밀값을 가린 실제 요청·응답, 건수, 저장값, 검사 결과 |
| ⑤ AI와 나 | AI에게 맡긴 일 / 내가 직접 판단한 일 / 따르지 않은 제안 또는 없었던 이유 | 실제 작업·판단 기록만 사용 |
| ⑥ 아직 못 막은 것 | 한계 1개 이상과 왜 위험한지 | 실제 미구현·미해결 범위, 필요한 후속 조치 |

실제 5일의 질문·지표·단위·계산·계획, 규칙 변경 시각/이유/1~2일차 참조, 같은 기준 전후 비교, 화면 합계·평균과 손계산, 내보내기·계정 삭제 처리/안내의 근거도 전달한다. 이 연결은 제출 내용을 준비하기 위한 정리이며 별도 추가 보고서나 추가 첨부를 공식 필수로 만든 것이 아니다.

현재 로컬 근거는 verification/auth-local.json·auth-browser.json과 로그인/합성 화면 3장, 설명은 docs/AUTH-IMPLEMENTATION.md에 있다. **AI 보관 제안:** 소스 문서와 검증 기록을 연결하고, 시험 자료는 실제 사용자 자료와 구분해 표시한다. 합성 자료를 사용한 시험이라면 합성이라고 명시하며, 합성 시험의 통과는 실제 5일 사용 완료가 아니다. 이 문서에는 사용자 실제 기록과 판단을 만들어 넣지 않았다.

제출 화면은 결과물 URL·소스 URL 모두 필수라고 명시한다. 빈 화면의 “결과 주소, 소스 주소 또는 제출 파일 중 하나를 넣어 주세요”는 현재 버튼 상태 문구이며 공식 필수값을 선택값으로 바꾸지 않는다. 과제별 URL·파일 개수·권장 형식과 달라도 경고 확인 뒤 제출할 수 있다는 안내와 과제 완주 여부도 구분한다.

선택 과정 기록은 제출·승인에 영향이 없다. 제출은 시간·장소와 관계없이 언제든 가능하며 강의장 실습 시간은 프리미엄 연결에만 적용된다. 흐름은 과제 제출→강사 승인→마스터 승인이다. **이번 작업에서 과제 제출 버튼을 누르지 않았다.**

제출 초안은 공통 형식에 따라 docs/SUBMISSION.md에 작성했다. 공개 URL·실제 이관·5일 기록·최종 판단이 남아 최종 제출 문안 완료를 주장하지 않는다.
