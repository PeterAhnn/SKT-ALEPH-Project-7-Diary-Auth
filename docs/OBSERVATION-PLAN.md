# T07 실제 5일 관찰 준비

**사용자 확정:** 주제는 기존 ALEPH 공부·과제 진행, 지표는 `완료한 할 일 수`, 단위는 `개`다. 2026-10-02 사용자의 선택 응답에 근거한다. 질문·첫 규칙은 사용자 채택 완료. 실제 날짜별 완료 수·규칙 변경·해석은 아직 기록하지 않았다.

아래 계산 기준은 **AI가 선택해 구현한 규칙**이며, 앱의 관찰 시작 화면에서 사용자가 읽고 확정해야 자기 관찰 기준이 된다. 질문·첫 계획 규칙은 사용자가 제안을 채택했다. 계산 기준은 시작 화면의 별도 동의 답을 기다린다. 관찰 저장·화면·규칙 변경·손계산 대조·전체 export는 현재 로컬 구현 및 합성 검사를 마쳤다.

## 질문과 첫 규칙 제안

질문 최신 제안: “하루 시작에 ALEPH 할 일을 정하면 하루 완료 개수는 어떻게 달라질까?”

첫 규칙 최신 제안: “하루 시작에 ALEPH 할 일 3개를 정하고 진행한다”. 질문·첫 규칙을 묶어 사용자에게 확인 요청했다. 사용자가 제안한 질문·첫 규칙 사용을 선택했다. 관찰 시작 저장은 계산 동의 뒤 수행한다. 변경할 규칙은 실제 1~2일차 기록을 보고 정하며, 그 전에 변경 이유·관찰 결과를 만들지 않는다.

## 앱에서 읽고 확정할 계산 기준

| 항목 | 구현한 규칙 |
|---|---|
| 날짜 | Asia/Seoul 날짜가 서로 다른 정확히 5일. 공식은 서로 다른 날짜이며 연속 5일이라고 임의로 강화하지 않는다. |
| 하루 값 | 관찰 대상 계획의 할 일 중 그 날짜에 완료 이벤트가 있는 고유 task ID 수. 같은 날짜 같은 할 일을 완료/재열기/재완료해도 한 번. 다른 날짜 다시 완료하면 그 날짜에 한 번. |
| 관찰 대상 | 1일차에 지정한 T07 관찰 계획. 과거 T06 이관 기록은 별도 보존하고 관찰 값에 섞지 않는다. |
| 삭제·중복 | 완료 이벤트는 보존하며 이후 할 일 삭제로 과거 완료 개수가 바뀌지 않게 한다. request_id 중복과 날짜/task_id 중복을 따로 막는다. |
| 누락 | 기록 안 한 날은 ‘미기록’. 사용자가 0개를 확인한 날만 실제 0. 미기록을 0으로 자동 변환하지 않고 5일 완성으로 세지 않는다. |
| 이상치 | 큰 값도 그대로 보존하고 날짜 확정 전에 메모로 설명한다. 임의 제거·대체하지 않는다. 현재 확정 기록의 정정 기능은 없으며, 잘못 확정했다면 원본과 한계를 보존하고 새 관찰에서 다시 시작한다. |
| 합계·평균 | 합계는 각 날짜 정수 개수의 합. 평균은 확인한 날짜 수로 나눈다. 전체 비교는 5일이 모두 확인된 뒤, 변경 전 2일과 변경 후 3일을 같은 기준으로 계산한다. |
| 반올림 | 합계는 정수, 평균은 소수 1자리에서 표시하며 양수 half-up. 손계산 원값과 표시값을 함께 대조한다. |
| 주 시작 | 주간 표시가 필요하면 월요일. 전후 비교 단위는 주가 아니라 2일/3일이다. |
| 변경 | 2일차 실제 기록을 마친 뒤·3일차 사용 시작 전에 계획 규칙 딱 하나만 바꾼다. 시각·이전/다음 규칙·이유·1~2일차 참조 ID를 보존한다. 질문·지표·단위·계산은 유지한다. |

완료 개수는 하루의 작업 크기 차이를 반영하지 않으므로 실제 변화 해석에 이 한계를 적는다. 평균 증가만으로 규칙이 원인이라고 단정하지 않는다.

## 날짜 확정과 변경 동작

- 서버의 한국 현재 날짜만 확정할 수 있다. 날짜·완료 개수는 사용자가 임의로 보내지 않는다. 화면을 열어 둔 사이 날짜가 바뀌면 다시 불러와야 한다.
- 하루 확정 뒤에는 그 날짜에 관찰 계획의 추가 완료를 막고, 값·task/event ID·메모·확정 시각을 보존한다. 잘못 확정한 날을 임의 수정하는 기능은 없다. 하루를 모두 마친 뒤 확인한다.
- 시작한 날짜의 1일차를 놓치면 새 관찰 계획을 만들어 다시 시작한다. 서로 다른 5일이며 중간 날짜가 비어 있어도 0으로 만들어 채우지 않는다.
- 2일차 확정 전, 두 번째 변경, 실제 1~2일차 참조 불일치, 변경 없는 3일차, 6번째 날짜를 서버에서 거절한다.
- 질문·첫 규칙·계산 기준, 확정한 날짜, 한 번의 변경, 손계산 대조 기록은 DB에서 update/delete를 거절한다. 계정 삭제는 해당 파일 전체를 삭제한다.
- 손계산 칸은 자동으로 채우지 않는다. 사용자가 입력한 합계와 소수 1자리 평균을 비교해 일치할 때 대조 메모와 함께 보존한다. 이 기능의 통과가 사용자의 실제 계산 행동을 대신 증명하지 않는다.

검사: observation-local.json·observation-browser.json은 가상 시각과 합성 값으로만 확인했다. 실제 T07 5일 기록은 현재 없다.

## 남길 실제 자료

1. 1일차: 실제 질문·지표·단위·계산 규칙·관찰 계획·첫 규칙을 고정한 기록.
2. 매일: 실제 할 일·완료 이벤트·기여 task ID·당일 확인·메모. 0개인 날도 사용자 확인을 남긴다.
3. 변경: 실제 1~2일차를 참조하는 이유, 단 하나의 규칙 변경, 실제 서버 시각과 사용자 판단.
4. 5일차 후: 5일 및 2일/3일 합계·평균 손계산과 화면 대조, 전체 export 한 파일, 실제 한계·소감.

날짜를 앞당겨 만들거나 합성 값을 실제 기록으로 제출하지 않는다. 현재 실제 5일 기록은 **0일**이다.
