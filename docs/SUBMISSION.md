## 인증 구현 설명서

인증 방식은 **직접 구현한 Node 인증 라우트 + 서버 DB 세션**이다. 앱 0.3.0, Vercel Node 24, 비밀번호 처리는 내장 `crypto.scrypt`, 공개 DB는 Supabase PostgreSQL 17.11.0.002, 연결 패키지는 pg 8.23.1이다. T06의 자료·이력과 작업 로직을 이어 쓰고 매 요청 서버 세션을 확인해 로그아웃 즉시 기존 인증값을 거절하려고 이 구성을 사용했다. 대안으로 Supabase Auth를 검토했지만 기본 JWT 검증만으로 즉시 재사용 거절을 보장할 수 없고 별도 세션 확인이 필요하므로 현재는 DB 공급자로만 사용했다. 직접 구현에 따른 유지·검토 부담과 이메일 소유 확인 부재는 설명서 ⑥에 남겼다.

[AUTH-IMPLEMENTATION.md](./AUTH-IMPLEMENTATION.md)의 여섯 항목은 직접 Node 인증/crypto.scrypt/DB 세션과 Vercel Node 24·Supabase PostgreSQL 17.11.0.002·pg 8.23.1, 대안/이유·소스 위치·성공/거절·실제 한계를 설명한다. 공개 운영 API/화면 합성 근거를 연결했으며 본인 T06 이관은 actual-migration.json의 7표 digest 일치로 확인했다. 실제 5일 근거는 확보 후 추가한다. 별도 PDF나 첨부 파일은 공식 필수가 아니다.

## 재현·통과 확인 4가지 (권장)

- 어디로 가나요: https://skt-aleph-project-7-diary-auth.vercel.app 의 로그인 첫 화면.
- 무엇을 하나요(3단계 이내): ① 가입 후 로그인 ② 내 계획/할 일을 저장하고 새로고침 ③ 로그아웃 뒤 다이어리 주소 열기.
- 무엇이 보이면 통과: 로그인 후 내 계정 자료만 보이고 저장이 유지되며 로그아웃 뒤 로그인 화면이 나온다. 최종 제출에는 가린 양방향 거절·무변경·5일 집계 근거도 연결한다.
- 안 될 때: 로그인 없이 자료 API는 401, 다른 계정 자료는 404, CSRF/origin 오류는 403, 저장소 연결 실패는 503이다. 앱을 다시 불러와 로그인하고 입력을 보존한 채 다시 시도한다. 오류 화면과 실제 기록을 보관한다.

## AI와 내 판단 3줄 (권장)

- AI에게 맡긴 일: 현재 코드 이력 연결, 인증·계정 분리 구현, 합성 자동/브라우저 검사, 공식 기준과 구현 설명 연결.
- 내가 판단한 일: 관찰 지표를 ‘완료한 할 일 수(개)’로 선택했고 현재 T06 전체 자료의 이관을 선택했다. 제안한 질문과 첫 규칙을 채택했고 직접 본인 계정을 만들어 로그인했다. 실제 기록 해석과 AI 제안을 따르지 않은 일/이유는 아직 미확정이다.
- AI 말을 안 들은 일: 사용자의 실제 거절 또는 그 이유는 아직 기록이 없다. ‘없다’는 사용자 확인 없이 만들어 쓰지 않고 최종 제출 전에 실제 판단을 기록한다.
